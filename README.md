# 黑神话：悟空文化地图

**黑神话：悟空文化地图**（Black Myth: Wukong Cultural Atlas）是一个中英双语的静态文化探索网站。项目以《黑神话：悟空》的六回旅程为入口，把游戏中的地点、人物、器物和故事，与《西游记》原著及有公开证据支持的现实文化遗产联系起来。

本项目为 **CMU 82-439《黑神话悟空和西游记》课程**制作，用于课程研究、文化解读与交互展示。

它不是战斗攻略、全收集指南或官方资料站，而是一份可以沿着游戏路线阅读的数字文化展览：

> 游戏中的呈现 →《西游记》中的出处与改编 → 现实文化与实地遗产

## 项目目的

《黑神话：悟空》大量使用了《西游记》中的人物、情节和名称，也吸收了中国古代建筑、雕塑、宗教艺术与民间文化的视觉资源。游戏中的这些元素并不总是对原著的直接复现，也不能只凭视觉相似就认定某处场景来自某座现实寺庙。

本项目希望做到四件事：

1. **以游戏作为进入古典文学的入口。** 让没有完整读过《西游记》的访客，也能从一个角色、一件法宝或一处地点开始阅读原著。
2. **说明游戏如何改编原著。** 区分“原著直接出现”“原著元素重组”和“游戏原创扩写”，不把游戏设定当作小说原文。
3. **谨慎连接现实文化遗产。** 只有在政府、文博机构、新闻报道或其他可追溯资料明确支持时，才展示具体的现实地点、造像或采风关系。
4. **让每一项判断都能回到来源。** 阅读卡保留来源编号和链接，方便继续查阅、核对和讨论。

## 核心功能

- **六回章节探索**：从黑风山、黄风岭、小西天、盘丝岭、火焰山一路读到花果山。
- **交互式路线示意图**：点击地图印记，查看人物、妖王、地点、建筑、器物和故事；路线表示章节的先后与分支，不代表真实地理比例，也不是官方地图。
- **三层文化阅读卡**：并列呈现游戏中的内容、《西游记》原文与改编方式，以及有独立证据时才出现的现实文化遗产部分。
- **筛选与顺序阅读**：可按内容类型或知识层筛选，也可在地图下方依次展开本回的全部阅读卡。
- **可追溯引用**：每张卡片的原著、游戏流程和现实文化判断都通过来源 ID 连接到“资料来源”页。
- **中英双语**：中文页面位于 `/`，英文页面位于 `/en/`；切换语言时保留当前页面和锚点。
- **静态预渲染**：中英文共 20 个主页面在构建时写入完整 HTML，便于搜索、分享，也能在关闭 JavaScript 时继续阅读正文。
- **响应式与无障碍支持**：支持键盘操作、清晰焦点、移动端阅读、减少动态效果，以及窄屏地图的横向浏览。
- **独立音频控制**：悬浮播放器可在三首背景音乐之间切换，并记住背景音乐的开关与上次曲目；页头的界面点击音效使用另一套独立开关。

目前网站包含 **6 回、47 张文化阅读卡和 48 条来源记录**。

## 资料来源

项目把不同来源限定在各自能够证明的范围内。当前 48 条公开引用分为三类：

### 1. 古籍原文（22 条）

主要使用维基文库可查阅的中文原文，包括：

- 《西游记》相关回目；
- 《封神演义》原文入口，用于区分梅山七怪与《西游记》中的梅山人物；
- 柳宗元《蝜蝂传》、李白《代别情人》等与游戏命名或文化意象有关的文本。

古籍链接只用于证明“文本中写了什么”。网站保留所引中文原文；英文页面中的译文是本项目的工作翻译，不使用仍受版权保护的现代出版英译本。

### 2. 游戏流程与位置资料（20 条）

游戏内的区域顺序、隐藏路线、人物位置和物品获取方式，参考并交叉核对了游民星空、PowerPyx、Game8、IGN、哔哩游戏 Wiki、游侠网等公开攻略或流程资料。

这类来源用于说明游戏里“在哪里、怎样出现、如何进入”，不能单独证明文学出处或现实文化原型。游戏科学官网和 Steam 官方页面中的图片也被用于内部视觉研究，但未获得公开使用许可的文件不会进入公开构建。

### 3. 现实文物与文化遗产资料（6 条）

现实文化部分主要使用政府与新闻机构公开页面，包括晋城市人民政府、高平市人民政府、检察机关网站转载报道、文旅部门报道及央视新闻相关转载资料。它们用于核实府城玉皇庙二十八宿彩塑、隰县小西天悬塑、高平铁佛寺等对象与游戏之间被公开说明的联系。

现实文化来源只能证明报道中明确提到的“采风”“建模”“场景对照”或“文化关联”，不能外推为整座寺庙、全部角色或所有建筑构件都被游戏直接复制。

完整来源及每条证据的适用范围见：

- [`src/data/sources.json`](src/data/sources.json)：网站实际使用的来源索引；
- [`KNOWLEDGE_BASE.md`](KNOWLEDGE_BASE.md)：事实边界、章节研究与待考证项目；
- [`assets/research/`](assets/research/)：地图拓扑、图片来源和素材研究记录。

## 图片、素材与版权

项目严格区分“可公开发布素材”和“只供研究的参考图”：

- 项目地图、山形意境和界面视觉为原创设计，不代表游戏实机、真实寺庙或官方美术；
- 部分历史插图和文化遗产照片来自 Wikimedia Commons，使用公版或 CC BY-SA 4.0 素材，并保留作者、原始页面、许可和修改说明；
- 部分游戏画面来自已获本项目使用授权的第三方资料页面，只有与阅读节点准确对应且已登记为 `cleared` 的文件才会进入公开页面；
- 未明确授权、仅供研究或来源状态未知的素材不会进入公开构建；
- 生成式图像不得冒充游戏截图、历史书页、文物照片或现实遗产证据。

逐图署名和许可见 [`assets/ATTRIBUTION.md`](assets/ATTRIBUTION.md)，素材状态见 [`src/data/media.json`](src/data/media.json) 与 [`assets/research/ASSET_SOURCE_CATALOG.md`](assets/research/ASSET_SOURCE_CATALOG.md)。

## 证据原则

项目不会把下列关系混为一谈：

- **原著直接出现**：人物、地点、器物或情节可在原文中找到；
- **原著元素重组**：游戏保留了名称或母题，但重写了人物关系、经历或功能；
- **现实文化对照**：现实文物有助于理解游戏视觉，但没有证据表明开发者直接采用；
- **开发者确认采用**：需要主创、官方资料或可靠报道明确说明采风、扫描、建模或取景关系。

如果某项现实关联没有足够证据，网站会直接省略该部分，而不是用猜测、占位文字或视觉相似补齐。例如，第一回目前没有经过核实的现实寺庙原型，因此不会为黑风山强行绑定其他章节使用的山西古建。

## 技术实现

- React 19
- Vite 6
- React Router 7
- TypeScript
- Tailwind CSS 4
- Zod 数据校验

项目是纯静态前端，不包含后端、数据库、账号系统或 CMS。章节内容存放在本地 JSON 中，构建时生成中英文静态页面。

## 本地运行

需要 Node.js 22.x。

```bash
npm ci
npm run dev
```

生产构建与本地预览：

```bash
npm run build
npm run preview -- --port 4173
```

常用检查：

```bash
npm run validate
npm run typecheck
npm test
```

`npm run build` 会依次运行数据验证、TypeScript 检查和测试，然后构建浏览器端与临时服务端产物，最终把全部静态页面输出到 `dist/`。`.ssr/` 仅用于预渲染，不代表项目需要线上服务器。

## 数据质量门槛

构建会在以下情况失败：

- 引用的来源 ID 或素材 ID 不存在；
- 公开页面引用了未获许可的素材；
- 现实文化条目没有独立来源；
- 《西游记》条目没有回目或原文摘引；
- 路线示意图使用了未经拓扑资料支持的节点或连接；
- 中英文字段缺失、照抄或数量不一致；
- 页面直接显示内部枚举值或没有双语标签的许可状态。

这些门槛用于防止一条缺少证据的陈述，以普通正文的形式悄悄进入网站。
